## 系列帖正文要点（逐帖）

### 第 1 帖：先分清概念 + 动手前查版本

**正文要点：**
- 概念区分：HA 自带 MCP 只能操作已暴露给 Assist 的设备；ha-mcp 给的是管理级工具（建/改自动化、脚本、仪表盘、注册表、日志、备份）。只想语音开关灯的，用自带功能即可，不必装。
- 总规矩先行：ha-mcp 有四种跑法（进程内集成 / App / Docker / 本地 stdio），**每个 AI 客户端只能配一条**，留两条是官方点名的连接挂死头号原因；本系列主线只走进程内集成。
- 查版本动作：设置 → 关于 看版本号，对照矩阵选路：
- 2026.11+：设置 → Marketplace 搜 HA-MCP 安装（HACS 已内置改名；HA-MCP 在默认目录，不用连 GitHub、不用加自定义仓库）
- 2026.8.0–2026.10：HACS 搜 HA-MCP → Download
- 2026.7：只能手动 + 外部服务器降级路，不推荐新手
- 低于 2026.7：装不了，先升级 HA
- 提醒项：Marketplace 首次打开的警告要先接受；老名字 “HA-MCP Custom Component” 搜 HA-MCP 也能命中。
- 名字对照表：HACS→Marketplace、Add-ons→Apps、旧 SSE（8087）已移除。
- 端口速记：进程内直连 9584 / App 9583 / Docker 8086 / 旧 SSE 8087。

### 第 2 帖：主线安装——进程内集成七步走

**正文要点（完整步骤，照做）：**
1. 装集成：Marketplace 搜 “HA-MCP” → Install（或 HACS Download；或手动把仓库的 `custom_components/ha_mcp_tools/` 拷到 HA 配置目录的 `custom_components/` 下）。手动装后日志出现 “has not been tested by Home Assistant” 是所有自定义集成的例行提醒，不是报错。
2. **重启 HA**（设置 → 系统 → 重启）：不重启新代码不生效、添加集成里搜不到；刚重启完等页面稳定再操作（实测教训：后台未就绪时抢着提交，会出现账号已建但响应丢失的怪事）。
3. 先建专用管理员账号（下一帖详解）或备好自己的长期令牌。
4. 设置 → 设备与服务 → 添加集成 → 搜 HA-MCP → 选 **HA-MCP Server**（不要选 File & YAML Tools，那是 beta，新手跳过）。
5. 填表：凭据二选一（专用账号用户名/密码，或自己的长期令牌）+ 远程访问选 **Secret URL**（新手首选）+ 直连绑定按需选；提醒：新装默认远程关、直连只绑本机，什么都不选就只有本机能连。
6. 等首次启动：系统自动按固定版本装 ha-mcp 并在进程内拉起，1–2 分钟起步，不是卡死；成功会有通知。
7. 到条目 **Configure 页复制 Connect URL**：通知和日志里故意不打印它；该 URL 等于管理员钥匙，不截图外发；占位示例 `https://ha.example.com/api/webhook/mcp_请替换为你的随机串`，局域网直连示例 `http://192.168.1.10:9584/private_请替换为你的随机串`（地址换成读者自己的）。
- 实测背书一句话：作者按此链路在 HA 2026.11.1 上跑通 initialize → 工具列表 → 读全屋概览/状态 → 写待办并读回 → 重启后再次全部成功。

### 第 3 帖：凭据与安全姿态

**正文要点：**
- 两方式对照表：自己账号长期令牌（快，但泄露后任何网络可用、改动记你名下）vs 专用管理员账号（推荐，换到的令牌只在本地/回环可用、改动记专用账号名下）。
- 专用账号逐步建法：设置 → 人员 → 添加人员 → **允许登录 开 / 仅本地访问 开 / 管理员 开** → 用户名如 `ha-mcp`、独立强密码 → 把它的用户名密码填进第 2 帖的表单；系统自动签发令牌，密码不保存。
- 红线：表单的账号密码栏**绝不能填自己的账号**；填错只报笼统 `invalid_login`，先回人员页核对三个开关。
- 长期令牌逐步建法：头像 → 安全 → 长期访问令牌 → 创建；只显示一次，当场保存；粘贴不带引号不多空格；失效后在 设置 → 修复 看 “HA-MCP needs an administrator access token” 提示，删旧重建。
- 必须用管理员凭据的原因：普通令牌调用管理工具报 `AUTH_INSUFFICIENT_PERMISSIONS`，还会被 HA 计入失败登录、可能触发 IP 封禁。
- 连通后保命动作：侧边栏 HA-MCP 面板先开**只读模式**跑一周；工具开关改完要重启服务器 + 刷新客户端工具列表；设备页 **Access 开关**关掉会同时断三条路，「突然全连不上」先查它；别把该开关暴露给语音助手。

### 第 4 帖：远程访问选型 + 地址泄露怎么办

**正文要点：**
- 三模式表：Secret URL（地址即密码，新手首选）/ HA 登录（公网暴露时官方建议优先，客户端需支持 OAuth，回调地址可能要加白名单）/ legacy（少数客户端才用，改凭据或开关后必须**完整重启整个 HA**）。
- 直连 9584：局域网桌面客户端用，明文 HTTP 只在可信内网；新装默认只绑本机，要选局域网绑定。
- 公网入口分流：已有 Nabu Casa/反代 → 直接套现成域名，进程内集成**不需要**再装 Webhook Proxy（那是 App 路径的，老教程易误导）；完全没入口 → Cloudflare Tunnel/自建反代走 443；只给 ChatGPT 又不想暴露公网 → 社区 OpenAI Tunnel 类集成（第三方，出问题找该项目）。
- 轮换操作：Configure 页勾 **Regenerate connect secrets now** 提交，webhook 与直连串一起换新，旧地址立即失效，再逐个客户端更新；删条目重加也会轮换但要重配。

### 第 5 帖：连第一个客户端——Claude.ai

**正文要点：**
- 云端三条硬规则（本帖核心）：①连接器从 AI 厂商云端发起，地址必须公网可达，局域网地址永远连不上；②只走 **443、无显式端口**，带 `:8123` 的地址对连接器等于不存在，用反代/隧道转 443，HA「外部 URL」里填的地址也不能带端口；③Cloudflare 的 AI bots 拦截/地域封锁会拦厂商出口段，授权交换约 10 秒超时，慢反代间歇失败；Tailscale Funnel 同理用 443。
- 自测法：手机关 Wi-Fi 用流量打开连接地址，能打开（返回 405 也算通，原因见排障帖）才算真通。
- 添加步骤：设置 → Connectors → Add custom connector → 只粘 URL，OAuth 让它**自动探测**，不要手动硬选（含不要选「不登录」）；添加后点 Connect 并在同意页 Allow；自定义连接器需 Pro/Max/Team/Enterprise 套餐（以官方当前说明为准）。
- 验证法：开新对话问 “Can you see my Home Assistant? List the tools you have for it.”，能列出工具（[发布当天复核：默认工具数 / 含 opt-in 总数]）并读出真实实体状态才算通；只显示已连接但没工具，去排障帖 B 组。

### 第 6 帖：其他客户端对照帖（逐个给配置）

**正文要点（地址统一用 `<URL>` 指代 Configure 页复制的那条，替换成读者自己的）：**
- **Claude Desktop**：不能直填 URL，用桥：`{"mcpServers":{"home-assistant":{"command":"npx","args":["-y","mcp-remote","<URL>","--allow-http"]}}}` 写进 `claude_desktop_config.json`（macOS：`~/Library/Application Support/Claude/`；Windows 传统版：`%APPDATA%\Claude\`）；`--allow-http` 仅局域网 http 地址时加；需 Node ≥ 20.18.1；保存后**完全退出**（Cmd+Q / Alt+F4）重开；服务器 key 别带括号（会静默变 0 工具）。
- **Claude Code**：`claude mcp add-json home-assistant '{"url":"<URL>","type":"http"}'`，改完 `/mcp` 重连或开新会话。
- **Codex**：`codex mcp add home-assistant --url <URL>`；个别版本 HTTP 初始化会「工具为 0」，改走 stdio 对照（见第 10 帖）。
- **Cursor**：`{"mcpServers":{"home-assistant":{"url":"<URL>"}}}`，改完重启 Cursor。
- **VS Code**：`{"mcp":{"servers":{"home-assistant":{"type":"http","url":"<URL>"}}}}`，顶层是 **`mcp.servers` 不是 `mcpServers`**（新手第一大错）。
- **Gemini CLI**：`~/.gemini/settings.json` 里 `{"mcpServers":{"home-assistant":{"httpUrl":"<URL>"}}}`，键名是 **`httpUrl`**。
- **Windsurf**：`{"mcpServers":{"home-assistant":{"serverUrl":"<URL>"}}}`，键名是 **`serverUrl`**。
- **ChatGPT**：设置里建 connector 粘公网 HTTPS 地址；工具列表会被缓存，更新后点 **Refresh tools**，不行就删连接器**换名重建**。
- 一页对照表：客户端 × 顶层键 × 地址键名 × 备注（同小报童版对照卡）。

### 第 7 帖：第一次让 AI 干活（三个可复制开场）

**正文要点：**
- 前提动作：先开只读观察（第 3 帖）；放开写之前先 **设置 → 系统 → 备份** 做一次备份。
- 开场 1（建自动化）：「看一下我家的实体列表，帮我建一条自动化：日落后 15 分钟打开客厅灯，23 点关掉。建之前先把你的计划说给我听，我确认后再写入。」
- 开场 2（仪表盘卡片）：「把天气预报和客厅温湿度做成一张卡片，加到我的默认仪表盘最上面。先告诉我你打算用哪些实体。」

### 第 8 帖：排障手册（上）——连不上组

**正文要点（现象 → 原因 → 解法，编号沿用全系列统一坑号）：**
- 坑 1 双装冲突：同客户端留两条 ha-mcp 会转圈/挂死/时好时坏；只留一条，换路先删旧条目。
- 坑 2 版本不够：搜不到集成/`Requirements … not found`/配置流中止写明需 2026.8.0；回第 1 帖版本表先升级。
- 坑 3 不重启 + 首启慢：装完先重启 HA；首启装包 1–2 分钟起步不是卡死；地址只在 Configure 页有，通知/日志没有是设计如此。
- 坑 4 刚启动完抢着操作：页面能开 ≠ 后台就绪，实测出现过建号响应丢失、重提报用户名已存在；等页面稳定再动手。
- 坑 7（云端连不上）：回第 5 帖三条硬规则逐项对：公网可达？443 无端口？Cloudflare 拦截/封锁？外部 URL 带没带端口？
- 坑 16 端口对不上：9584（进程内）/9583（App）/8086（Docker）/8087（旧 SSE 已移除，连它会 405）。
- 坑 17 代理/杀毒劫持 HTTPS：uv 报证书 UnknownIssuer、客户端一闪就断；uv 加 `UV_NATIVE_TLS=1`，Node 加 `NODE_EXTRA_CA_CERTS=<pem路径>`；「本机能跑、换环境就崩」先查代理环境变量（实测有代理变量写法异常直接让程序启动崩溃的案例）。
- 坑 18 首次太慢：先终端跑 `uvx ha-mcp@latest --version` 预热缓存，再回客户端连，别在首拉超时时乱改配置。
**互动引导：** 提问格式：坑号或症状 + 已试步骤 + 打码日志。

### 第 9 帖：排障手册（下）——没工具 / 调用失败 / 附录路径组

**正文要点：**
- B 组（没工具/工具不对）：
- 坑 10 Claude Desktop 工具为 0：服务器 key 带括号被静默丢弃；key 只用字母数字空格下划线短横线，改完完全退出重开；Codex 个别版本同症改 stdio。
- 坑 11 工具列表过期：调用报 `VALIDATION_FAILED`/`unknown parameter`（服务器会纠正旧参数名并列出有效参数，实测亲历）；刷新法按客户端：Desktop 断开重连、Claude.ai 在连接器设置 Refresh tools list 后开新对话、ChatGPT Refresh tools 或删连接器换名重建、Claude Code 跑 `/mcp`；改工具开关后也要刷新。
- 坑 9 键名抄错：回第 6 帖对照卡逐字核，能用官方设置向导现生成就别抄万能 JSON。
- C 组（调用失败/安全）：
- 坑 5 凭据填错栏：`invalid_login` 先核对专用账号三开关；红线是别把自己账号密码填进专用账号栏。
- 坑 6 非管理员令牌：报 `AUTH_INSUFFICIENT_PERMISSIONS` 且可能触发 IP 封禁；只用管理员令牌，中招先查封禁记录。
- 坑 8 地址泄露：截图先打码 `/api/webhook/` 后段；已泄露按第 4 帖立即轮换并逐个客户端更新。
- 坑 15 改 OAuth 只重启条目：legacy 改动必须整机重启 HA，再删连接器重加；进程内集成不需要 Webhook Proxy。
- D 组（Docker/uvx 专用）：
- 坑 12 Python 版本：9.x 需 Python ≥3.13，旧版 pip 报 `No matching distribution found`，还可能装到远古 3.x；用 uvx（自动拉对的 Python，已实测）或 `uvx --python 3.13 …`，工具变少先 `uv cache clean` + `uvx --refresh`。
- 坑 13 Docker 设置丢/端口：数据在容器内 `~/.ha-mcp` 必须挂卷（compose 里 volume 写死名字）；端口映射第二位与 `MCP_PORT` 两处一致改；日志出现 `data will NOT persist` 就是没挂对。
- 坑 14 默认路径裸奔：HTTP 模式必须设秘密路径 `MCP_SECRET_PATH=/private_你的随机串` 或只绑回环；设对后浏览器 GET 返回 **405 是正常**（只收 POST），错路径 404，别把 405 当故障。
**互动引导：** 排障成功后欢迎回帖写下你的症状和解法，沉淀成星球内的互助索引。
