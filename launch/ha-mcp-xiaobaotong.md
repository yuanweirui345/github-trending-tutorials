# 正文

## 第 0 章 先说清：ha-mcp 和 HA 自带 MCP 不是一回事

Home Assistant 自带了面向 Assist 的 MCP 能力，但它只能操作**已经暴露给语音助手的那部分设备**（开灯、关灯这类）。

ha-mcp 给 AI 的是**管理级工具**：建和改自动化、脚本、仪表盘、场景，查注册表与日志，做备份等。实测的默认工具集就能覆盖「配置管理」而不只是「设备控制」。

一句话判断你需不需要这篇：
- 只想语音开灯关灯 → 用 HA 自带功能就够了，不用买、不用装。
- 想让 AI 帮你**写自动化、改配置、排故障** → 这就是 ha-mcp 的活，继续往下看。

另外先立一条总规矩，后面会反复用到：**ha-mcp 有四种跑法（进程内集成 / App / Docker / 本地 stdio），但每个 AI 客户端只能配其中一条。** 同一个客户端里留两条（比如一条旧的 uvx 命令、一条新的集成地址），是官方明确点名的「连接挂死」头号原因。本教程主线只走第一种：进程内集成。

在 HA 里打开：**设置 → 关于**，看版本号。再对照下表选路：

| 你的 HA 版本 | 怎么装 | 说明 |
|--------------|--------|------|
| **2026.11 或更新** | 设置 → **Marketplace** 搜 HA-MCP → Install | 2026.11 起 HACS 已内置并改名 Marketplace；HA-MCP 在默认目录里，**不用连接 GitHub、不用添加自定义仓库** |

| **2026.7** | 只能手动拷贝组件，且进程内 Server 条目会被系统拦截 | 只能走「手动组件 + 外部服务器（App/Docker）」降级路，新手不建议 |
| **低于 2026.7** | **装不了** | 先升级 Home Assistant，再回来装 |

**方式一（推荐，HA 2026.11+）**：设置 → Marketplace → 搜索 “HA-MCP” → 点 Install。

## 第 3 章 凭据与安全姿态（这章别跳，卖点和保命都在这里）

### 3.1 两种凭据方式对照

| | 方式一：自己账号的长期令牌（快） | 方式二：专用管理员账号（推荐） |
|--|------------------------------|------------------------------|
| 做法 | 头像 → 安全 → 长期令牌 → 创建，复制后粘进表单的令牌栏 | 设置 → 人员 → 添加人员，填它的用户名/密码进表单 |
| 泄露后果 | 该令牌**在任何网络都能用**，约等于把管理员钥匙挂在公网 | 它换到的令牌**只在本地网络/回环可用**，泄露面小得多 |
| 审计 | AI 的所有改动记在**你名下** | 改动记在专用账号名下，一眼分清哪些是 AI 干的 |

实测结论：方式二（专用账号）在实测中一次通过，且是官方推荐姿态。本教程主线按方式二走。

### 3.2 方式二：建专用管理员账号（逐步）

1. 设置 → 人员 → 添加人员。
2. 三个开关这样设：
   - **允许登录（Allow login）：开**
   - **仅本地访问（Local access only）：开**
   - **管理员（Administrator）：开**
   [截图待补：添加人员页三个开关同框]
3. 给它起个好认的名字，比如用户名 `ha-mcp`，显示名 “HA-MCP Server”，设一个独立的强密码（不要和你自己的 HA 密码相同）。
4. 回到第 2 章步骤 5 的表单，把**这个专用账号的用户名和密码**填进去。提交成功后，系统会自动为它签发令牌，密码本身不会被保存。

> ⚠️ **红线：表单的用户名/密码栏，绝不能填你自己的账号。** 官方原话就是不要用自己的登录走这一路。用自己账号，就改走方式一粘长期令牌。填错时表单只报一个笼统的 `invalid_login`，不告诉你错在哪——先回来核对这三个开关，多半是漏了「仅本地访问」或没给管理员。

### 3.3 方式一：建长期令牌（逐步）

1. 点左下角你的头像 → **安全（Security）** → 找到 **长期访问令牌（Long-lived access tokens）** → 创建令牌，起个名如 “ha-mcp”。
2. 令牌**只显示一次**，当场复制保存好。
   [截图待补：创建长期令牌的页面（发布示例会用废令牌演示并打码，请勿截自己的真令牌发帖）]
3. 粘进表单的令牌栏时注意：**不要带引号、不要多空格**，前后多一个空格都会失败。
4. 令牌过期或被吊销后，服务器下次启动校验失败，你会在 设置 → 修复 里看到 “HA-MCP needs an administrator access token” 的修复提示，删掉旧令牌重建一张即可。

### 3.4 为什么必须用管理员凭据

用普通（非管理员）账号的令牌，表面能连上，但一调用建自动化、改配置这类工具就报 `AUTH_INSUFFICIENT_PERMISSIONS`；更麻烦的是，HA 会把这类未授权请求计入失败登录，攒多了可能触发 IP 封禁。所以：**只用管理员凭据**，中招了先去 HA 里看封禁记录，换管理员凭据重来。

### 3.5 连通后的两个保命开关

1. **只读模式先开一周**：侧边栏打开 **HA-MCP 面板**，先开启 Read Only Mode（只读），让 AI 只能看不能改，观察一周没问题再放开写权限。工具的启停也在这个面板里管理，注意：改完工具开关要**重启服务器并刷新客户端的工具列表**才生效。
   [截图待补：侧边栏 HA-MCP 面板首页（工具开关/只读模式）]
2. **Access 开关**：条目的设备页有一个 Access 开关，关掉它等于同时切断 webhook、直连、对话代理三条路。如果哪天「突然全连不上」，先来这里看它是不是被关了。
   [截图待补：设备页 HA-MCP Server 的 Access 开关]
   注意：不要把这个开关实体暴露给语音助手，也小心那种作用于「全部实体」的自动化误伤它。

## 第 4 章 选远程访问模式（一张表选清）

### 4.1 三种身份模式 + 直连

| 模式 | 是什么 | 适合谁 | 代价 |
|------|--------|--------|------|
| **Secret URL**（`none`） | 连接地址里的随机串本身就是密码，形如 `https://你的域名/api/webhook/mcp_随机串` | 新手首选、最快连通 | 地址泄露=钥匙泄露；泄露后立即轮换（见 4.3） |
| **HA 登录**（`ha_auth`） | 客户端跳转到 HA 登录页，用管理员账号登录授权 | 要把地址暴露到公网时，官方建议优先 | 客户端需支持 OAuth；个别客户端的回调地址要加进 Configure 页的回调白名单（默认已含 claude.ai、chatgpt 等主流域名） |
| **legacy** | 老式自托管 OAuth，要把一对 Client ID + Secret 粘进客户端 | 少数只认这种凭据的客户端 | 改这组凭据或开关此模式后，**必须完整重启整个 HA** 才生效，只重启条目没用 |
| 局域网直连（9584） | `http://HA局域网地址:9584/private_随机串` | 同一局域网的桌面客户端 | 明文 HTTP 只在可信内网用；新装默认只绑本机，要选局域网绑定才通 |

### 4.2 你的公网入口从哪来（按情况分流）

- **已有 Nabu Casa 或反向代理指向 HA**：什么都不用多装，连接地址直接套你现有的域名即可。进程内集成**不需要**再装什么 Webhook Proxy（那是 App 路径的东西，老教程最容易在这里让你多装一个）。
- **完全没有公网入口**：用 Cloudflare Tunnel 或自建反向代理，把 HA 通过 **443 端口**送上公网（为什么必须是 443，见第 5 章的三条硬规则）。
- **只给 ChatGPT 用、又不想暴露公网**：可考虑社区的 OpenAI Tunnel 类集成（第三方项目，出问题找该项目，不要找 ha-mcp 官方）。

### 4.3 地址泄露了怎麼辦：轮换

打开条目 Configure 页 → 勾选 **Regenerate connect secrets now（立即重新生成连接密钥）** → 提交。webhook 地址和直连随机串会一起换新，**旧地址立刻失效**，然后逐个客户端把新地址填回去。
[截图待补：Configure 页 Regenerate connect secrets 的位置]

删除条目重新添加也会轮换，但要重走一遍配置，不如直接用这个开关。

## 第 5 章 连你的第一个客户端：Claude.ai（网页版）

> 这一章的客户端界面截图需真实付费账号环境补拍，步骤文字已写全：
> [截图待补：Claude.ai 添加自定义连接器并连接成功、工具列表展开]

### 5.1 动手前先记住三条硬规则（云端客户端连不上的结构性原因）

1. 连接器是**从 AI 厂商的云端服务器**发起连接的，不是你的浏览器——所以地址必须**公网可达**，局域网地址在云端永远连不上。
2. 托管连接器只走 **443 端口、无显式端口号**。`https://ha.example.com:8123/...` 这种带 `:8123` 的地址，你在浏览器里能打开，对连接器等于不存在。要用反代/隧道把 443 转进来，HA 本体继续留在 8123。**在 HA 的「外部 URL」设置里填的地址也不能带端口。**
3. 如果你用了 Cloudflare：关掉它的 “Block AI training bots” 类拦截、别对厂商 IP 段做地域封锁；这类拦截会让「浏览器能开、连接器连不上」，而且授权交换有约 10 秒超时，慢反代会间歇失败。

自测方法：手机关 Wi-Fi、用流量打开你的连接地址，能打开（哪怕返回 405，405 是正常的，见第 8 章）才算公网真的通。

### 5.2 添加步骤

1. 准备好第 2 章步骤 7 复制的连接 URL（公网版）。
2. Claude.ai → 设置 → Connectors（连接器）→ Add custom connector（添加自定义连接器）→ 只粘贴 URL，其他 OAuth 选项**让它自动探测**，不要手动硬选（包括不要手选「不登录」），手选是常见连不上原因。
3. 添加后点 **Connect（连接）**，在弹出的同意页点 Allow。
4. 需要的套餐：Claude.ai 自定义连接器需 Pro / Max / Team / Enterprise 套餐（以官方当前说明为准）。

### 5.3 验证连通（每个客户端都这样验）

开一个**新对话**，问它：

```
Can you see my Home Assistant? List the tools you have for it.
```

能列出工具（实测时默认工具集为数十个，[上架当天复核：默认工具数 / 含 opt-in 总数]），再让它读一下全屋概览或某个实体状态，能返回真实数据就是真通了。只显示「已连接」但列不出工具，按第 8 章「有连接、没工具」一组排查。

## 第 6 章 其他客户端逐个连（对照卡）

总原则：**地址只有一条**——就是 Configure 页复制的那条；每家客户端的配置**键名都不一样**，抄错一个字母就连不上，而且大多不报明确错误。下面逐个给，配置里的 `<URL>` 全部替换成你自己的连接地址，**令牌和随机串不要发给任何人看**。

### 6.1 Claude Desktop（桌面版，不能直接填 URL）

Claude Desktop 只认本地命令，要用 `mcp-remote` 当桥。把下面这段写进 `claude_desktop_config.json`：

```json
{
  "mcpServers": {
    "home-assistant": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "<URL>", "--allow-http"]
    }
  }
}
```

- 配置文件位置：macOS 在 `~/Library/Application Support/Claude/`；Windows 传统版在 `%APPDATA%\Claude\`（商店版路径请查官方说明）。
  [截图待补：Claude Desktop 配置文件粘贴桥配置前后 + 重启后出现工具图标]
- `--allow-http` 只在你的地址是局域网 `http://` 时才加；`https://` 地址删掉这个参数。
- 需要 Node.js ≥ 20.18.1。
- 保存后必须**完全退出** Claude Desktop 再重开（macOS 用 Cmd+Q，Windows 用 Alt+F4），关窗口不算。
- 服务器名字（上面例子里的 `home-assistant`）**只能用字母、数字、空格、下划线、短横线，别带括号**——带括号会让工具数静默变 0 且毫无报错（第 8 章坑 10）。

### 6.2 Claude Code

```bash
claude mcp add-json home-assistant '{"url":"<URL>","type":"http"}'
```
改完在会话里运行 `/mcp` 重连，或直接开新会话；旧会话不会自动刷新工具。

### 6.3 Codex

```bash
codex mcp add home-assistant --url <URL>
```
已知个别版本有 HTTP 初始化问题，表现为同一地址在别的客户端正常、这里「连上但工具为 0」，遇到就改走本地 stdio 方式（附录 B 的 uvx 写法）对照。

### 6.4 Cursor

项目或全局的 MCP 配置里写：
```json
{
  "mcpServers": {
    "home-assistant": { "url": "<URL>" }
  }
}
```
改完重启 Cursor。

### 6.5 VS Code（最容易抄错的一家）

```json
{
  "mcp": {
    "servers": {
      "home-assistant": { "type": "http", "url": "<URL>" }
    }
  }
}
```
注意顶层是 **`mcp.servers`，不是 `mcpServers`**——把 Claude/Cursor 的格式原样抄过来是新手第一大错。

### 6.6 Gemini CLI

`~/.gemini/settings.json` 里写：
```json
{
  "mcpServers": {
    "home-assistant": { "httpUrl": "<URL>" }
  }
}
```
键名是 **`httpUrl`，不是 `url`**。

### 6.7 Windsurf

```json
{
  "mcpServers": {
    "home-assistant": { "serverUrl": "<URL>" }
  }
}
```
键名是 **`serverUrl`**，又不一样，照抄别家的必错。

### 6.8 一页对照速查

| 客户端 | 顶层键 | 地址键名 | 备注 |
|--------|--------|----------|------|
| Claude.ai / ChatGPT | 界面填 | — | 见第 5 章 / 6.9 |
| Claude Desktop | `mcpServers` | 走 mcp-remote 桥 | 必须完全退出重开 |
| Claude Code | 命令行 | `url` + `type:"http"` | `/mcp` 重连 |
| Codex | 命令行 | `--url` | 工具为 0 时改 stdio |
| Cursor | `mcpServers` | `url` | 改完重启 |
| VS Code | `mcp.servers` | `url` + `type:"http"` | 顶层键不同！ |
| Gemini CLI | `mcpServers` | `httpUrl` | 键名不同！ |
| Windsurf | `mcpServers` | `serverUrl` | 键名不同！ |

### 6.9 ChatGPT

设置里新建 connector，粘贴公网 HTTPS 地址（或走第 4 章的 OpenAI Tunnel 路）。
[截图待补：ChatGPT 连接器设置页与 Refresh tools 按钮]
注意：ChatGPT 会**缓存工具列表**，教程更新或工具变化后，在插件设置里点 **Refresh tools**；还不生效就把连接器删掉、**换一个名字**重建，同名重建会继续吃旧缓存。

## 第 8 章 排障手册（18 个真实踩坑，按症状查）

> 用法：先按你的症状跳到对应组，再逐条对。标注 [实测] 的是作者实测亲历，[文档] 的来自官方 README/FAQ/文档明示。

### A 组：连不上

**坑 1：一个客户端配了两条 ha-mcp** [文档]
现象：连接转圈、挂死、时好时坏。
原因：以前用 uvx/Docker 装过没删，又加了集成/App 的地址，两个服务器抢同一个 HA。
解决：只留一条。换路前先去客户端把旧条目删干净，再加新的；四种跑法四选一。

**坑 2：HA 版本不够还硬装** [文档]
现象：添加集成搜不到 HA-MCP；或日志报 `Requirements for ha_mcp_tools not found`；或配置流直接中止并写明需要 2026.8.0。
原因：进程内 Server 最低要 HA 2026.8.0，低于 2026.7 集成根本加载不了。
解决：回第 1 章版本表，先升级 HA。

**坑 3：装完不重启 / 首次启动慢以为卡死** [文档+实测]
现象：商店里显示装好了，添加集成里却没有；或提交条目后半天没动静。
原因：集成代码只在启动时加载；首启还要现装固定版本的 ha-mcp 包，1–2 分钟起步。
解决：装完先重启 HA 再添加集成；提交后耐心等通知，连接地址去 Configure 页拿（通知/日志里没有地址是设计如此）。

**坑 4：HA 刚启动完就抢着提交表单** [实测]
现象：实测首启期间提交建号请求，长时间无响应，账号实际已建成但授权响应丢失，重提报 `Username "…" already exists`。
原因：页面能打开 ≠ 后台已就绪，慢机器首启要数分钟。
解决：重启/首启后等页面稳定、日志出现启动完成再操作。普通用户对应场景就是一句：刚重启完，别连点。

**坑 7（编号按草稿）：局域网能连、云端连不上** [文档]
现象：浏览器打开地址正常、同局域网的 Claude Code 正常，Claude.ai / ChatGPT 死活连不上。
原因：回第 5.1 节三条硬规则——云端发起、必须 443 无端口、Cloudflare 的 AI 拦截与地域封锁、授权交换约 10 秒超时；Tailscale Funnel 同理必须 443。
解决：手机流量自测；关 Cloudflare 的 AI bots 封锁并放行厂商出口段；外部 URL 里填的地址去掉端口。

**坑 16：端口/名字对不上号** [文档+实测]
速记：进程内直连 9584 / App 9583 / Docker 8086 / 旧 SSE 8087（已删除）。拿 9583 的老教程连进程内安装必然失败；旧的 SSE 入口已被移除，拿它连新服务会返回 405。

**坑 17：代理/杀毒劫持 HTTPS** [文档+实测变体]
现象：uvx 下载报证书错误（UnknownIssuer），或客户端里服务器一闪就断。
原因：公司代理、Zscaler、杀毒软件的 HTTPS 扫描证书，不被 uv（自带证书库）或 Node 信任。
解决：uv 加环境变量 `UV_NATIVE_TLS=1`；Node 加 `NODE_EXTRA_CA_CERTS=<你的pem证书路径>`。实测旁证：本次实测环境里代理变量 `NO_PROXY` 带了括号写法的 IPv6 条目，直接让程序启动时抛 `Invalid port` 崩溃，清掉异常条目立刻恢复——「在本机能跑、换个环境就崩」时，先查代理环境变量。

**坑 18：第一次打开太慢** [文档+实测]
现象：uvx 首跑、HA 首载组件都要现下载几十 MB（实测冷启拉了新版 Python 加 71 个包）。
解决：先在终端单独跑一次 `uvx ha-mcp@latest --version` 预热缓存，再回客户端连接；别在客户端首拉超时时乱改配置，越改越乱。

### B 组：连上了，但没工具 / 工具不对

**坑 10：Claude Desktop 工具数为 0** [文档]
现象：显示已连接、握手都成功，模型侧一个工具都没有，毫无报错。
原因：配置里服务器的 key 带了括号（如 `Home Assistant (ha-mcp)`），派生工具名不合规被客户端静默丢弃。
解决：key 只用字母、数字、空格、下划线、短横线，改完完全退出重开。Codex 的个别版本也有「工具为 0」的已知问题，对照 6.3 节改 stdio。

**坑 11：工具列表过期、调用被拒** [文档+实测]
现象：调用报 `VALIDATION_FAILED` 或 `unknown parameter`。实测中把参数写成旧名时，服务器原文回复会纠正：`` `search_query`: unknown parameter, did you mean `query`? `` 并列出有效参数。
原因：客户端缓存了旧工具列表，重启 HA 不会刷新它。
解决：Claude Desktop 断开重连；Claude.ai 在连接器设置里 Refresh tools list 后开新对话；ChatGPT 点 Refresh tools，还不行删连接器**换名重建**；Claude Code 跑 `/mcp`。

**坑 9：客户端配置键名抄错** [文档+实查]
现象：JSON 没报错，但服务器不出现。
原因与解法：回第 6 章对照卡逐字核对（VS Code 是 `mcp.servers`、Gemini 是 `httpUrl`、Windsurf 是 `serverUrl`），能用官方设置向导按「客户端 × 安装方式」现生成的配置，就别抄博客的万能 JSON。

### C 组：能连，但调用失败 / 安全相关

**坑 5：凭据二选一填错栏** [文档]
现象：表单报 `invalid_login`，密码明明没错。
原因：专用账号栏只收「仅本地访问 + 管理员」账号且不说明具体原因；把自己的账号密码填进去也会被拒（红线见 3.2）。
解决：用自己账号改走粘长期令牌；用专用账号回人员页核对三个开关。

**坑 6：拿普通账号令牌硬连** [文档]
现象：建自动化/改配置报 `AUTH_INSUFFICIENT_PERMISSIONS`，甚至触发 IP 封禁计数。
解决：只用管理员令牌；中招先查 HA 的封禁记录。

**坑 8：把 Secret URL 当普通链接分享/截图** [文档]
现象：发帖求助把完整 webhook 地址截进去，等于公开管理员钥匙。
解决：截图先打码 `/api/webhook/` 后面部分；已泄露按 4.3 立即轮换，再逐个客户端更新地址。

**坑 15：改了 OAuth 却只重启条目** [文档]
现象：改 legacy OAuth 开关/凭据后客户端报 `Invalid client id`。
原因：这类视图在集成首次加载时绑定，重启条目/App 不生效。
解决：设置 → 系统 → 重启整个 HA，再删客户端连接器重加。另注意：进程内集成自带 webhook，不需要再装 Webhook Proxy（那是 App 路径的）。

### D 组：附录路径专用（Docker / uvx 自托管）

**坑 12：Python 版本坑** [实测]
现象（原文）：Python 3.12 的 pip 报 `No matching distribution found for ha-mcp==9.1.2`；强指旧 Python 时报不满足 `Python>=3.13,<3.15`。
原因：ha-mcp 9.x 需要 Python ≥ 3.13；旧解释器还可能默默装上远古 3.x 版本。
解决：用 `uvx`（它会自动拉对的 Python，实测自动下载并跑通），或显式 `uvx --python 3.13 ha-mcp@latest`；用 `--version` 核对版本，工具变少先 `uv cache clean` 再 `uvx --refresh`。

**坑 13：Docker 设置全丢 / 改端口只改一处** [文档]
现象：容器一重建，工具开关、注册信息全没了；或改了端口永远连不上。
原因：数据在容器内 `~/.ha-mcp`，不挂卷就随容器销毁；端口要在映射的第二个数字和 `MCP_PORT` 两处一致修改。
解决：固定挂载数据卷（compose 里给 volume 写死名字）；看到日志出现 `data will NOT persist across restarts` 就是没挂对。

**坑 14：ha-mcp-web 裸奔默认路径** [实测]
现象（原文警告）：服务监听在 `0.0.0.0:8086/mcp` 并使用默认路径——等于没密码还绑了所有网卡。
解决：自托管 HTTP 必须设高随机度的秘密路径（如 `MCP_SECRET_PATH=/private_换成你的随机串`）或只绑本机回环。顺带记住：设对后，用浏览器 GET 这个地址返回 **405 是正常的**（该端点只收 POST），错误路径返回 404，设置页返回 200——别把 405 当故障。

## 附录 A：App（add-on）路径速览

- 仅 HAOS / Supervised 可用：到 Apps 商店装 HA-MCP App，启动后从**该 App 的日志**里复制它打印的连接地址（端口 9583）。
- App 路径要让云端客户端连入，通常需再装 Webhook Proxy App 把流量借道 HA 的 8123 出去。
- 此路径未在作者实测环境（Core 安装）验证，步骤以官方文档为准；遇到与正文不一致处，以官方文档和项目 issue 为准。

## 附录 B：Docker / uvx 自托管速览

Docker（概念命令，镜像与变量名以官方文档为准）：
```bash
docker run -d --name ha-mcp \
-e HOMEASSISTANT_URL=http://192.168.1.10:8123 \
-e HOMEASSISTANT_TOKEN=请替换为你的管理员长期令牌 \
-e MCP_SECRET_PATH=/private_请替换为你的随机串 \
-v ha-mcp-data:/home/mcpuser/.ha-mcp \
-p 8086:8086 \
ghcr.io/homeassistant-ai/ha-mcp
```
要点：必须挂数据卷（坑 13）；必须改秘密路径（坑 14）；改端口两处一致。

不用 Docker 时用 uvx 跑 HTTP 模式（已实测本体可跑通）：
```bash
uvx ha-mcp@latest --version # 先核对版本并预热缓存
```
再按官方文档以 `ha-mcp-web` 入口启动，并设置与上面相同的环境变量。

本地 stdio 对照写法（仅排障对照，官方不推荐长期用）：
```json
{
"mcpServers": {
"Home Assistant": {
"command": "uvx",
"args": ["ha-mcp@latest"],
"env": {
"HOMEASSISTANT_URL": "http://192.168.1.10:8123",
"HOMEASSISTANT_TOKEN": "请替换为你的管理员长期令牌"
}
}
}
}
```
注意：Claude Desktop 这类图形应用不继承终端 PATH，报 `uvx not found` 时把 `command` 写成 uvx 的**绝对路径**。
