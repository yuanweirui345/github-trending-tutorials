## 一、实测日志（2026-11-10，沙箱真实执行）

### 环境
- Ubuntu 24.04.5 LTS，Python 3.12.3，x86_64
- 沙箱初始**没有 pipx、没有 Docker、没有 uv**。先用 venv 装 pipx：
  - `python3 -m venv /tmp/sherlock-venv`（约 4 秒）
  - `/tmp/sherlock-venv/bin/pip install pipx` → pipx 1.18.16（约 8 秒）
- 以下所有时间均为沙箱实测，沙箱为非中国大陆网络环境；涉及大陆网络的结论单独标注依据，不冒充实测。

### README 要点（官方）
- 一句话：输入一个用户名，一次检查它在 **400+ 社交网络**上是否存在对应账号页面。
- 安装：`pipx install sherlock-project`（也可用 pip / uv 代替），或 `docker run -it --rm sherlock/sherlock`；另有 Debian/Ubuntu/Homebrew/Kali 等社区包（官方提示 ParrotOS 与 Ubuntu 24.04 的第三方包已损坏，建议用 pipx/pip/uv 或 Docker）。
- 基本用法：`sherlock user123`；多用户名：`sherlock user1 user2 user3`
- 常用参数：`--site SITE` 只查指定站（可重复）、`--timeout` 单站超时（默认 60 秒）、`--print-found` 只看命中、`--print-all` 全部输出、`--proxy socks5://127.0.0.1:1080` 走代理、`--csv/--xlsx` 导出、`--txt` 生成 txt 结果文件、`--nsfw` 包含成人站点（**内容创作中不要开启、不要展示**）。
- 版本：README 内示例为 0.16.0；本次实际安装到 **0.16.2**。

### 安装实测：第一次失败，第二次成功（重要踩坑）
| 尝试 | 命令 | 结果 | 耗时 |
|---|---|---|---|
| 第 1 次 | `pipx install sherlock-project` | ❌ 失败。下载依赖 pandas 的 12.4 MB wheel 时网络中断，pip 自动续传 6 次只收到 1.3 MB，报 `error: incomplete-download`，pipx 随即删除了未完成的 venv，表面上看像「装了个寂寞」 | 约 54 秒后失败 |
| 第 2 次 | `pipx install sherlock-project --pip-args="--resume-retries 10"` | ✅ 成功，`installed package sherlock-project 0.16.2`，生成 `sherlock` 命令 | 约 37.5 秒 |

结论：安装本身一条命令，但**大依赖（pandas）对网络很敏感，网络不稳就会半途失败且不留痕迹**。教程/视频里必须提醒：失败先重试、换稳定网络，不要以为是工具坏了。
`sherlock --version` 输出：`Sherlock v0.16.2`

### 查询实测 1：最小查询（限定 5 个站，公开测试用户名 `github`）
```bash
sherlock --print-found --no-color --timeout 20 \
  --site GitHub --site Twitter --site Instagram --site Reddit --site YouTube github
```
- 耗时：**23.1 秒**（只查 5 个站也要 20 多秒，主要是慢站/无响应站在等超时）
- 命中 2 个：
  - `[+] GitHub: https://www.github.com/github`
  - `[+] Reddit: https://www.reddit.com/user/github`
- Twitter / Instagram / YouTube 未返回命中。**这不等于这些平台上没有该用户名**，只能说明在本机网络 + 20 秒超时内没拿到可判定的响应——假阴性真实存在，写内容时必须讲清。

### 查询实测 2：全站查询（同一公开测试用户名 `github`）
```bash
sherlock --print-found --no-color --timeout 15 github
```
- 耗时：**66.8 秒**，最终 `Search completed with 117 results`
- 命中样例（均为公开主页链接）：GitHub、Reddit、TikTok、Telegram、Twitch、Steam、Pinterest、Threads、Substack、Wikipedia、VK、Vimeo、ProductHunt、Pastebin 等
- 注意：若用默认超时 60 秒，全站跑完会比 67 秒明显更久；官方生态文档给的经验值也是单次约 30–120 秒起。**做视频演示务必先用 `--site` 限定几个站，或提前录好加速播放。**
- 小坑：0.16.2 默认**不**自动生成结果 txt 文件，需要加 `--txt` 才会落文件（和一些老教程写的不一样，老教程已过时）。

### 查询实测 3：负样本（随机不存在的用户名，只查 GitHub）
```bash
sherlock --print-all --no-color --timeout 15 --site GitHub zzztest999888xyz
```
- 耗时：**4.6 秒**，结果 `GitHub: Not Found!`，`Search completed with 0 results`
- 对比说明：站点响应快时整个查询只要几秒；慢的是「等某些站超时」，不是工具本身在算。

### 查询实测 4：国内平台覆盖（关键限制）
- 本地站点库 `data.json` 实际共 **482 个站点**（与官方「400+」宣传一致）。
- 尝试 `--site Bilibili --site Weibo --site Zhihu` 直接报错：`Error: Desired sites not found: 'Bilibili', 'Weibo', 'Zhihu'.`
- 即：**B站、微博、知乎等国内主流平台不在站点库里**（全库按名称检索也没有这几个站）。这个工具查的主要是海外平台，对国内用户最实用的场景是：查自己在海外平台的注册/占用情况、做自媒体出海前的网名统一性检查。

### 现实限制汇总（写进内容，不许藏）
1. **要查全海外平台，大陆网络需要代理。** 工具专门有 `--proxy` 参数（如 `sherlock 你的用户名 --proxy socks5://127.0.0.1:1080`）就是为这种场景准备的。无代理时，很多站会超时或无响应，结果会明显不全（本次沙箱非大陆网络，不直接冒充大陆实测；此条依据是站点库以海外站为主 + 平台可达性常识 + 工具的代理设计）。
2. **「查到」≠「是同一个人」。** 它只判断「某平台上存在这个用户名的公开页面」。同名不同人非常普遍，尤其是短词、常见英文名。
3. **「没查到」≠「没注册」。** 超时、被站点拦截、私密账号、站点改版都会造成漏报（实测 1 就是例子）。
4. **速度不稳定。** 5 个站 23 秒、全站约 67 秒（15 秒超时档），默认参数更慢。耐心或缩小范围，二选一。
5. **国内平台基本查不到。** 不要对读者承诺「查遍全网」，准确说法是「查 400 多个海外平台」。

### 中文教程饱和证据（为什么不做付费）
中文搜索「sherlock 用户名查询 教程」前排已有：阿里云开发者社区完整教程、CSDN 实操长文、x-cmd 中文站安装页、中文博客专文，甚至有现成的中文版仓库 `sherlock-chinese` 和中文 README 的同类实现。基础安装教程已无空白，付费版没有立足点；流量做免费内容正合适。

## 二、公众号 / 小红书科普文草稿（可直接改后发布）

### 封面文案（小红书）
大字：`你的网名，有多少个分身？`
小字：`一条命令自查 400+ 平台 · 免费开源 · 附避坑`

### 正文

**先问你一个问题：你的网名，是从什么时候开始用的？**

QQ 年代起的那个 ID，你是不是一路用到了现在——游戏、论坛、视频站、代码托管、海外 App，全是同一个名字？

那你有没有想过：**这个名字，在你没注册过的平台上，是不是已经「存在」了？** 是别人恰好同名，还是有人特意用了你的名字？

有个 10 万 Star 的开源工具叫 Sherlock，做的就是这件事：给它一个用户名，它自动去 400 多个平台挨个确认「这个名字的页面存不存在」，最后给你一份清单。我们实测拿一个公开用户名跑完全量，**67 秒，查出 117 个平台有这个名字的账号**。

它最适合的用法，不是查别人，而是**查你自己**：

- 🧹 **清理旧账号**：很多人会查出一堆「原来我十年前还注册过这个」的遗忘账号，不用的趁早注销，减少信息残留。
- 🏷️ **做自媒体前先占坑自查**：准备全平台用同一个名字做账号？先查一遍哪些平台已经被同名占了，免得做到一半发现名字不统一，被迫改名。
- 🪞 **看看有没有「冒牌的你」**：如果你在某个平台查到一个用你名字、你却完全没注册过的活跃账号，记下来，走平台官方的冒充举报渠道处理，别自己去对线。

**怎么用（真的只有几步）：**

第 1 步，装工具（电脑上打开终端）：
```
pipx install sherlock-project
```
没有 pipx 也可以用 Docker：`docker run -it --rm sherlock/sherlock 你的用户名`
（实测提醒：安装会下载一个较大的依赖，网络不稳可能中途失败、还不留提示。失败了别慌，换个稳定网络重试一次就好，我们第一次就失败了，第二次 37 秒装完。）

第 2 步，先小范围试查，别一上来查全量：
```
sherlock --site GitHub --site Reddit --print-found 你的用户名
```

第 3 步，确认没问题再查全量（把超时调短一点，不然会等很久）：
```
sherlock --timeout 15 --print-found 你的用户名
```
结果想存成文件，加 `--txt`；导出表格加 `--csv`。

**看结果时，有三句话必须说清（这也是我们和那些夸张教程的区别）：**

1. **查到 ≠ 是你，也 ≠ 是某个人。** 它只能证明「这个平台上有这个用户名的公开页面」。同名的人满世界都是。
2. **没查到 ≠ 没注册。** 有的网站响应慢、有的会拦截自动请求，实测里就有明明存在却没返回的站。结果只能当线索，不能当结论。
3. **它查的主要是海外平台。** 站点库一共 482 个站，但 **B站、微博、知乎不在里面**。在国内网络直接查，很多海外站会超时，想查全需要给它配代理（参数是 `--proxy`）。别信任何「一键查遍全网」的说法。

**最后，一条边界，请认真看：**
这个工具只应该用来查**你自己的**用户名、你自己的品牌名，或者得到明确授权的账号。不要拿它去批量查别人的账号、拼凑别人的个人信息，更不要去打扰、联系查到的人——那既不礼貌，也可能踩到法律和平台规则的线。公开能查到，不等于可以随便用。

好玩归好玩，自查完记得做正事：不用的旧账号注销掉，重要账号开双重验证，同名被冒充就走官方举报。

你查完可以回来报个数：**你的网名一共查出了多少个「分身」？** 只报数字就好，用户名本身就别发评论区了，保护好自己。
