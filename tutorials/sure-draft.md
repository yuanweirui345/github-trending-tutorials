## 2. 资源占用（官方实测数据，非本沙箱实测）

来自官方文档 docs/hosting/docker.md「Running Sure on small (512 MB) hosts」，为官方在生产部署上的测量值：

| 场景 | 内存 |
|---|---|
| 稳态运行（仪表盘、记账、预算、报表、汇率刷新、少量同步/CSV 导入） | **约 352 MB**，512MB 上限可舒适运行 |
| 点「加载示例/演示数据」 | 约 680MB、约 5 分钟，**512MB 容器会被 OOM 杀掉且数据回滚** |
| 开启 AI 功能（助手/自动分类） | 官方建议 **至少 1GB** |
| 数万行级别首次大导入/历史同步 | 可能超 512MB，需分批导入或临时调高 worker 内存 |

给教程的结论（可直接写给学员）：
- **最低配**：512MB 内存的 VPS/NAS 能跑日常记账；**推荐 1-2GB**，留给导入和演示数据。
- 镜像自带 jemalloc + YJIT + Puma 1 worker×3 线程调优，学员不需要改这些。
- 磁盘：源码仅 74MB；镜像+PG 数据的实际占用未在本沙箱实测，教程定稿前在真机 `docker system df` 量一次再写数字，**不要凭估算印进教程**。

## 3. 中文与人民币核实（源码级确认）

### 3.1 中文界面：有，且覆盖较完整（已核实）
- 语言选项里有 `zh-CN: 简体中文`、`zh-TW: 繁體中文`（app/helpers/languages_helper.rb）。
- 语言文件计数：`config/locales` 下 zh-CN 文件 **163 个**，en 文件 174 个——按文件数覆盖约 94%，
  属于「主体界面已汉化」的水平；个别新功能页面可能仍显示英文，教程中应如实提示，不要承诺 100% 全中文。

### 3.2 人民币：完整支持（已核实）
- `config/currencies.yml` 中 CNY 定义齐全：Chinese Renminbi Yuan，符号 ¥，小数位 2。
- 初始化时可在货币列表中直接选 CNY；国家选 China 时默认货币自动带出 CNY
  （Family.default_currency_for_country 走 ISO3166 国家→货币映射）。

### 3.3 初始化流程（据官方文档 Step 4-5 + 引导页源码，还原如下）
1. `docker compose up` 拉镜像启动 → 浏览器打开 `http://<设备IP>:3000`（默认端口 3000，可用 PORT 改）。
2. 登录页点「create your account」注册第一个账号（邮箱+密码）——**第一个注册者即超级管理员**。
3. 引导页（onboardings/preferences）依次选：**语言 = 简体中文、货币 = CNY、日期格式**，再设家庭/目标等后续步骤。
4. 建第一个账户（手工账户）→ 开始记账；或通过导入功能上传 CSV 开始迁移旧账本。
5. **收尾必做**：到 Settings > Self-Hosting > Onboarding 把注册状态改成 **Closed**，
   防止局域网/公网其他人自行注册进你的实例（官方文档 Step 5a）。

## 4. ⚠️ 银行同步核实结论（教程红线，必须照此写，不许过度承诺）

**结论：Sure 不支持中国大陆银行同步，也没有支付宝/微信支付/银联的自动同步。国内用户只能手工记账 + 文件导入。**

证据（逐项查过）：
1. 官方 Plaid 文档第一句警告：**"Plaid integration currently only works for Western users"**（Plaid 覆盖北美/欧洲）。
2. 全部同步 provider 源码清单共 28 个，无一覆盖中国大陆银行：
   Plaid（北美/欧洲）、SimpleFIN（北美）、Enable Banking / TrueLayer（欧洲开放银行）、Akahu（新西兰）、
   Sophtron（美国）、Monobank（乌克兰）、Fio（捷克）、SnapTrade（海外券商）、LunchFlow，
   以及 Binance/Coinbase/Kraken 等加密货币交易所、Wise、Mercury、Brex 等海外机构。
3. 全仓库代码检索 `Alipay / WeChat / UnionPay / 中国银行名`：除国家名「China」和交易所列表外**零命中**。

国内用户可行的入账方式（这才是教程真正要教的）：
- **手工记账**：应用原生支持手工账户（Account.manual）与手工录入交易。
- **CSV 导入**：支持通用 CSV 交易导入（带列映射）；另有 QIF、PDF 导入，
  以及 Mint / YNAB / Monarch 等海外软件的迁移导入。
  → 教程可设计「支付宝/微信账单导出 CSV → 列映射 → 导入 Sure」的实操章节，
  但要标明这是**批量导入**，不是实时自动同步，且导入前需在表格里做简单清洗（此流程需真机补测后才能定稿）。

**文案红线**：标题、详情页、朋友圈文案中禁止出现「自动同步银行卡」「直连支付宝微信」「解放双手自动记账」等表述；
卖点只能落在「数据自托管、私密、可控、界面现代、支持中文和人民币」。

## 5. 教程大纲（定稿结构）

### 通用篇（两条路径共用）
1. 先说清它是什么、不是什么（含第 4 节红线、适合/不适合人群）
2. 准备工作：设备要求（内存建议）、域名要不要、备份意识
3. 初始化：注册管理员 → 切简体中文 → 货币 CNY → 日期格式 → 关闭公开注册
4. 建账：手工建银行卡/现金/支付宝/微信「手工账户」的方法（把支付工具当手工账户管）
5. 第一笔账 + 分类/标签/预算设置 + 净资产仪表盘怎么看
6. 账单迁移：支付宝/微信导出 CSV → 清洗 → 列映射导入 → 对账检查
7. 日常维护：升级（改镜像 tag / compose up -d）、官方 backup profile 定时备份、异地备份（rclone）
8. 进阶（选修）：反向代理 + HTTPS、SMTP 找回密码、AI 功能（需自备 API Key、会产生费用，默认不开）

### 路径 A：NAS 篇（飞牛 fnOS / 群晖 / 绿联）
1. 三家系统里 Docker/Container Manager 的 compose 项目入口在哪、如何新建项目
2. 粘贴本教程给的 compose.yml（已改好端口和密码占位）→ 一键拉起 4 个容器
3. 局域网访问、NAS 防火墙端口、开机自启检查
4. NAS 特别注意：演示数据按钮别在小内存机型上点（OOM 坑，见坑清单 #4）；数据卷落在哪个存储空间、如何跟 NAS 快照配合

### 路径 B：VPS 篇
1. 选购建议：1-2GB 内存起步；系统装 Docker Engine + Compose 插件（官方文档 Step 1 验证命令）
2. `mkdir ~/docker-apps/sure` → curl 拉官方 compose.example.yml 与 .env.example
3. 生成 SECRET_KEY_BASE（`openssl rand -hex 64`）、改 POSTGRES_PASSWORD
4. `docker compose up -d` → 公网访问前的必做三件套：反代 HTTPS（并把 RAILS_ASSUME_SSL 改 true）、关闭公开注册、防火墙只放行反代端口
5. 域名解析与证书、SMTP 配置（找回密码邮件）

## 6. 坑清单（现象 → 原因 → 解决；均有文档/源码依据）

1. **照抄示例 compose 直接公网裸奔** → 示例文件内置了默认 SECRET_KEY_BASE 和默认数据库密码
   （compose.example.yml 明文默认值）→ 本地局域网试玩无妨，**只要出局域网，必须在 .env 里换成自生成的随机值**。
2. **改了 .env 却不生效** → Compose 只把 compose.yml 中列出的变量传给容器；
   SMTP 等变量要按官方文档加进 `x-rails-env` 锚点，且要用 `docker compose up -d` 重建，
   `docker compose restart` 不会换环境变量。
3. **HTTPS 反代后登录异常/页面报错** → 忘了把 compose 中 `RAILS_ASSUME_SSL: "false"` 改为 `"true"`（官方文档明示）。
4. **点「加载演示数据」永远转圈、数据消失** → 生成器在 worker 里跑、需约 680MB，512MB 容器被 OOM 杀掉并回滚
   → 先给 worker 临时调高内存，生成完再调回去。
5. **第一次导入几年账单卡死** → 数万行大导入同样吃内存 → 分年份/分账户分批导入。
6. **汇率/股价同步报 `Failed to open TCP connection`（Yahoo Finance）** → DNS 先解析到 IPv6 而容器没配 IPv6
   → 示例 compose 已内置 8.8.8.8 / 1.1.1.1 DNS；仍不行按文件头注释加 extra_hosts 写死 IPv4。
   补充：汇率数据源默认可用免费的 Yahoo Finance（免 Key），或填 Twelve Data 的 API Key（二选一，.env 中配置）。
7. **邀请家人却收不到邮件** → 自托管实例**从不发送邀请邮件**（官方文档明示）；
   且没配 SMTP 时找回密码邮件也发不出 → 在设置页复制邀请链接手动发；SMTP 按坑 #2 的方法配。
8. **国内拉 ghcr.io 镜像慢/失败**（网络环境问题，非项目缺陷）→ 错峰重试或给 NAS/VPS 配可用的镜像加速；
   教程定稿时给出当时可验证的加速方法，**不要写死未经验证的镜像地址**。
9. **以为能自动同步国内银行，装完才发现不能** → 见第 4 节，这是预期管理问题，必须在售卖页和教程第一节就讲清。
10. **AI 功能开了账单惊讶** → OpenAI 兼容接口按量收费 → 默认保持关闭，需要时在官方文档建议下先给 Key 设消费上限。
